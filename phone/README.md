# Jericho Personal — Android offline edition

A separately installed, free personal tool. Package `org.insuredspending.jerichopersonal`, version 1.1-personal, Android 8+ (minimum API 26, target API 35). It does not replace the hosted Jericho app or access its accounts. There is no subscription, AI credit system or paid-provider connection. Local-model calls require your explicit setup and request.

## Use on a phone

Download `Jericho-Personal-1.0.apk`, open it in Android Files/Downloads, and follow Android's installation prompts. It is a privately signed personal APK, not a Play Store release. Do not disable Play Protect. Installation and native WebView/file-picker behavior still require acceptance on your actual device.

Create a project and choose Checklist, Notebook, or HTML app. Checklists and notebooks work directly inside the app and save on the device. HTML projects have a code editor, an isolated script-enabled preview and HTML export. Import a single HTML/text file or a version-1 personal JSON backup. Existing projects are retained; replaying an unchanged backup deduplicates it, and conflicting IDs become restored copies. All imports validate before a batch is applied. Use your keyboard's microphone for dictation if desired; Jericho requests no microphone permission.

Export app/text opens Android's document picker. Choose a destination and save. Back up all exports the complete project library, including source and notes, as plain JSON. Keep backups private. App data is not cloud-synced, and uninstalling/clearing storage removes it. Storage failures show a persistent warning and keep edits in memory; export before closing. Unreadable original storage is protected from overwrite during that session.

Offline editing remains available without a model. Version 1.1 can additionally generate and revise HTML apps through your own connected local model. It does not fetch GitHub repositories, import the consolidated source-reference catalog, run server projects, control other apps, or guarantee arbitrary application requirements are met. Generated checklist/notes exports are named templates. An HTML preview has temporary state and no network access; its code cannot access the workbench's saved projects. Exports are separate copies. Review arbitrary imported HTML before using it outside the isolated preview.

## Build and verify

Source: `assets/index.html` and `src/org/insuredspending/jerichopersonal/MainActivity.java`.

Requires Android SDK platform 35/build-tools 35.0.0, Java 17+, Eclipse ECJ 3.40.0, and the existing private signing key. `build.py` makes no network call and refuses a missing signing password. Configure `JERICHO_PHONE_SIGNING_PASSWORD` privately; never commit the key or password. Invoke `python3 phone/build.py --build-tools PATH --android-jar PATH --ecj PATH --keystore PRIVATE_PATH --out OUTPUT.apk`.

Version 1.0 had no network permission. Version 1.1 adds native INTERNET access for explicit local AI; it still requests no microphone, camera, contacts or broad storage permission. File access is user-selected through Android's document picker. There is no JavaScript interface exposed to frames. Native save prompts are accepted only from the bundled top-level asset URL. Remote loads and cross-file universal access are disabled; imported previews retain an opaque sandbox origin with no top navigation or file download permission. JavaScript syntax and APK signature checks do not prove a complete security audit or physical-device acceptance.

Browser acceptance: install Playwright in a separate test environment and run `node phone/test-browser.mjs`, optionally setting `JERICHO_PLAYWRIGHT_MODULE` and `JERICHO_BROWSER_EXECUTABLE`. It exercises real offline file loading, phone layout, task persistence, empty-list persistence, Unicode notes, backup replay, source preview interaction and isolation, exported app behavior and native-export payload encoding. Native compilation, DEX packaging, APK signatures (v2/v3), resource manifest and ZIP alignment are verified separately. Actual Android install, document picker, storage lifecycle and keyboard dictation remain device checks. There is no current-head GitHub CI evidence for this edition yet.

A private recovery package preserves the source, APK and signing materials for future updates. Keep that recovery copy private. Updates must use the same signing key and a higher versionCode; export a backup before any uninstall or replacement. Do not re-sign with a new identity over an existing install.

## Version 1.1 — local AI creation and revisions

This update adds **Build with local AI** and **Ask AI to change it**. Each request targets an existing local Ollama model on your own computer. It can generate single-file HTML apps and new revised copies. A result is a generated draft: use Run preview to exercise its controls, then export only after reviewing it. The phone itself does not contain the model. The computer must have Ollama and an appropriate local model installed and remain running on the same trusted network. This path makes no paid-provider API call; hardware, electricity and any model download still belong to your computer/network.

1. Back up your current projects and install 1.1 over 1.0. It uses the same package and signing identity; do not uninstall 1.0 to update it.
2. On the Windows computer, install Ollama from https://ollama.com/download/windows if needed and install a model that fits the computer. Do not choose a cloud model. No installer/model download is included or run by Jericho. An appropriate model depends on actual RAM/GPU; the application cannot establish that remotely.
3. Quit any existing Ollama tray/server process yourself if you want to use the supplied temporary launcher. Review `Start-Jericho-Local-AI.ps1`, identify the computer's private Wi-Fi IPv4 address, then run `& .\Start-Jericho-Local-AI.ps1 -BindAddress '192.168.1.20'` with your actual address. It binds only that private address and disables Ollama cloud features for that process. It does not stop existing services, alter persistent settings, open firewall ports, forward router ports or create a public tunnel. The computer's firewall may block incoming connections; no broad firewall change is made automatically.
4. In Jericho, choose Build with local AI, enter the displayed address, confirm the trusted network and check installed models. Choose an installed model, name the app and describe its behavior. Keep Jericho open until the result arrives. A check only lists models; it does not generate content or download a model.
5. Open an existing project and choose Ask AI to change it for revisions. The exact selected source is sent with the instruction; the result becomes a separate project. Source revisions currently accept at most 16,000 characters. No original is overwritten.

The launcher requires a trusted Windows Private network and an already-installed Ollama. A local Ollama API has no login. HTTP on the LAN is not encrypted, so do not expose it on public/shared Wi-Fi, a public IP, a reverse proxy or a tunnel. The native client accepts only explicit numeric loopback/private IPv4 origins with high ports, no credentials/URL paths/query, no redirects, and locally listed GGUF models with positive size/digest and no remote/cloud metadata. It rechecks model eligibility before the single generation POST. These checks rely on your trusted local server reporting its model metadata honestly. Set `OLLAMA_NO_CLOUD=1` on that server as the launcher does. No generation occurs until you explicitly submit an instruction.

The Android update declares INTERNET/cleartext support for the deliberate native LAN connection. WebView network loads remain blocked; imported/generated previews still have no network and no same-origin permission. HTTP response bytes, request size, input length and timeouts are bounded. Incomplete/truncated outputs fail without creating a replacement project or retrying. If the app closes during generation, its unsaved result may be lost while the computer continues working. Generation jobs are not durably recoverable across app termination in this version.

Run `phone/test-local-ai.mjs` with the same Playwright environment as the original browser suite. It uses synthetic native replies to verify consent, endpoint refusal, local-model selection, prompt/result import, preview interaction, source-bound revision, failures, and duplicate callback handling. `phone/test/LocalModelClientTest.java` uses a real loopback HTTP fixture to verify request contracts, source binding, one POST, cloud refusal, redirect refusal and no retry on truncated output. Compile it with ECJ and the test-only org.json JAR; the APK uses Android's built-in JSON implementation. A passing fixture is not a live model or owner-device acceptance.

Real local-model acceptance on October 29 used Ollama 0.40.13 with qwen2.5-coder:1.5b. A new counter app passed Add 1 and Reset in an offline 390px browser. A real source-bound revision added Subtract 1 and preserved both earlier actions. An earlier unchanged revision was detected; the client now refuses identical returned source, and the revised prompt places the requested change after the source. The smaller 0.5b model returned incomplete output and was rejected. The synthetic source/output, hashes and bounded acceptance receipt are in `phone/test/evidence/`. These are one simple app and revision, not arbitrary-app quality certification, a hardware recommendation for an unseen computer, or owner-phone acceptance.
