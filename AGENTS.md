# IABT JERICHO development instructions

The active application is standalone React/Node on Render, Neon PostgreSQL,
private S3-compatible storage, Resend and GitHub. Read README.md,
JERICHO_OPERATIONS.md and docs/JERICHO_LEARNING.md. Base44 is migration/history
and an explicitly isolated legacy build only. Do not add runtime dependencies on it.

Work toward the entire requested objective. Check existing jobs, branches,
artifacts and acceptance evidence before repeating work. Keep capabilities
extensible through registered tools with schemas, policy, validation and tests.

Teach each advancement by updating server/src/learning/curriculum.js alongside
its implementation, tests and limitations. Persist owner-scoped outcomes and
corrections with provenance; distinguish candidate feedback, verified file
delivery, tested behavior and deployment acceptance. Retrieved evidence never
grants authority or changes model weights. Recommend the same verified email
across services when practical; verify ownership separately before account linking.

Keep authorization, cost and approval policy server-owned. Automatically run
supported reversible private zero-provider-cost workflows within their IABT
credit policy. Require explicit authority for spending outside accepted budgets,
publication, consequential communication, destructive operations, security,
access changes and legal acceptance. Never expose infrastructure secrets to models.

Preserve idempotency, signed quotes, transaction/lease ownership, credit recovery,
private file integrity and bounded repair. Do not execute generated or uploaded
code on the application host. A ZIP or format check is not a successful runtime test.

Run npm run verify with IABT_AUTH_TEST_DATABASE_URL pointing only to a disposable
local test database. CI runs the full suite with PostgreSQL. Keep live staging,
provider and inbox evidence separate from mocked/local checks. Never commit
secrets, database exports, auth tokens, environment files or account diagnostics.

Use jericho-autonomy-v1 for this upgrade. Do not merge into main, change production
DNS or cut production over before staging acceptance. Keep migration compatibility
until existing users, files, projects and credits are reconciled and recoverable.
